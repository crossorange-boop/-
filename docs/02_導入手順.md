# AI統合管制システム 導入手順書

対象：Google Workspace アカウントのオーナー（システム管理者）
所要時間：初回 30〜45分程度
費用：0円（追加の有料サービス・有料APIは使用しません）

---

## 全体の流れ

| 手順 | 内容 | 実施場所 |
| --- | --- | --- |
| 1 | 準備（Node.js・Apps Script API の有効化） | 自分のPC／ブラウザ |
| 2 | コードの取得 | 自分のPC |
| 3 | clasp でログインし、Apps Script プロジェクトを作成 | 自分のPC |
| 4 | コードを Apps Script へ反映（push） | 自分のPC |
| 5 | 初回セットアップ（データベース作成・権限の承認） | Apps Script エディタ |
| 6 | 定期処理（トリガー）の登録 | Apps Script エディタ |
| 7 | Webアプリとして公開（自分のみ） | Apps Script エディタ |
| 8 | 導入確認（自己診断）とスマホでの表示確認 | Webアプリ |

> 手順 3 以降は実際の Google アカウントに変更を加えます。内容を確認しながら進めてください。
> 認証情報（`~/.clasprc.json`）は自分のPCにのみ保存され、リポジトリには含まれません。

---

## 1. 準備

### 1-1. Node.js（無料）をインストール
- https://nodejs.org/ から LTS 版をインストールします（Windows / Mac どちらでも可）。
- ターミナル（Windows は「PowerShell」、Mac は「ターミナル」）で確認します。

```bash
node -v
```

`v20` 以上が表示されれば OK です。

### 1-2. Apps Script API を有効にする
1. ブラウザで https://script.google.com/home/usersettings を開きます（導入する Google Workspace アカウントでログイン）。
2. 「Google Apps Script API」を **オン** にします。

---

## 2. コードの取得

GitHub のリポジトリ `crossorange-boop/-` のブランチ `ai-control-system` を取得します。

```bash
git clone -b ai-control-system https://github.com/crossorange-boop/- ai-control-system
```

```bash
cd ai-control-system
```

```bash
npm install
```

> git を使わない場合は、GitHub の画面で `ai-control-system` ブランチを選び「Code → Download ZIP」で取得し、展開したフォルダで `npm install` を実行します。

---

## 3. clasp でログインし、プロジェクトを作成

### 3-1. ログイン
```bash
npx clasp login
```
ブラウザが開くので、導入する Google Workspace アカウントを選び、アクセスを許可します。

### 3-2. Apps Script プロジェクトを作成
```bash
npx clasp create-script --type standalone --title "AI統合管制システム" --rootDir src
```
- `.clasp.json`（スクリプトIDの記録）が作成されます。このファイルはリポジトリには含めません。
- 作成時に `src/appsscript.json` が初期内容で上書きされる場合があるため、必ず元に戻します。

```bash
git checkout -- src/appsscript.json
```
（ZIP で取得した場合は、ダウンロードした ZIP の中の `src/appsscript.json` で上書きしてください。内容に `"timeZone": "Asia/Tokyo"` と `"access": "MYSELF"` が含まれていれば正しいファイルです。）

---

## 4. コードを反映

```bash
npx clasp push
```
- 「Manifest file has been updated. Do you want to push and overwrite?」と聞かれたら `y` を入力します。
- 反映されるファイルは `src/` 配下のみです（テストや文書は反映されません）。

---

## 5. 初回セットアップ（データベース作成）

1. Apps Script エディタを開きます。
   ```bash
   npx clasp open-script
   ```
2. エディタ上部の関数選択で **`setupSystem`** を選び「実行」を押します。
3. 初回は「承認が必要です」と表示されます。「権限を確認」→ アカウントを選択 → 内容を確認して「許可」します。
   - 要求される権限：スプレッドシート、Google ドライブ（バックアップ用）、トリガーの管理、メールアドレスの確認
   - メール送信・外部サービスへの送信の権限は要求しません。
4. 実行ログに作成結果が表示されます。
   - Google ドライブに **「AI統合管制システム_DB」**（データベース）と **「AI統合管制システム_バックアップ」**（フォルダ）が作成されます。
   - 11シート、初期AI 4件（Claude Code・Muse・Canva・Local / Rule Engine）、割り振りルール 4件、設定値が登録されます。
   - **実行したアカウントがオーナー**（全権限）になります。

> `setupSystem` は何度実行しても安全です。既存のデータは上書きせず、不足しているシート・列・設定だけを追加します。

---

## 6. 定期処理（トリガー）の登録

エディタで **`setupTriggers`** を選び「実行」します。次の6つが登録され、**PCを閉じていても Google のサーバー上で動作**します。

| 処理 | タイミング（初期値） |
| --- | --- |
| タスクキュー確認（自動振り分け） | 5分ごと |
| 期限・進捗確認 | 15分ごと |
| 朝の当日タスク一覧 | 毎日 7時台 |
| 昼の中間経過 | 毎日 13時台 |
| 夕方の進捗集計 | 毎日 17時台 |
| バックアップ | 毎日 3時台 |

- 日次の処理は Google の仕様で指定時刻から最大15分程度ずれます。
- 後から Webアプリの「設定・ログ → 自動処理」でも登録・停止・再設定できます。

---

## 7. Webアプリとして公開（自分のみ）

### 方法A：エディタから（おすすめ）
1. エディタ右上の「デプロイ」→「新しいデプロイ」。
2. 種類の選択で「ウェブアプリ」を選びます。
3. 設定を確認します。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**自分のみ**
4. 「デプロイ」を押し、表示された **ウェブアプリの URL** を控えます。

### 方法B：コマンドで
```bash
npx clasp create-deployment --description "v0.1.0"
```
```bash
npx clasp open-web-app
```

### スマホで使う
- 控えた URL をスマホのブラウザで開き、同じ Google アカウントでログインします。
- ブラウザのメニューから「ホーム画面に追加」すると、アプリのように起動できます。

---

## 8. 導入確認

1. Webアプリを開き、ダッシュボードが表示されることを確認します。
2. 「設定・ログ → システム情報 → 導入確認（自己診断）」の「点検する」を押します（エディタで `runSelfCheck` を実行しても同じです）。
3. すべて「問題なし」になれば導入完了です。
   - 「バックアップ：まだ実行されていません」は、「設定・ログ → 自動処理 → 今すぐバックアップ」を押すか、翌朝3時以降に解消します。
4. 動作確認として、テスト用のプロジェクトとタスク（例：タスク名「Instagram 投稿テスト」）を登録し、
   「作業待ちキュー → 今すぐ振り分け」で Muse に割り当てられることを確認します（確認後は削除して構いません）。

---

## 更新するとき（新しいバージョンの反映）

```bash
git pull
```
```bash
npx clasp push
```
- エディタの「デプロイ → デプロイを管理」で、既存のデプロイを編集し「バージョン：新バージョン」を選ぶと、**URL を変えずに**更新できます。
- 新しい設定項目やシートの列が追加された場合は、エディタで `setupSystem` を再実行します（既存データはそのまま、不足分だけ追加）。

---

## 他のメンバーを追加するとき（将来）

1. 「設定・ログ → 設定値 → ALLOWED_USERS」に `メール:ROLE` をカンマ区切りで登録します。
   - 例：`tanaka@example.com:EDITOR, suzuki@example.com:VIEWER`
   - ROLE：`EDITOR`（登録・編集可、承認・設定変更は不可）／`VIEWER`（閲覧のみ）
2. `src/appsscript.json` の `"access": "MYSELF"` を `"access": "DOMAIN"` に変更し、`npx clasp push` → デプロイを新バージョンに更新します。
   - ドメイン内のユーザーでも、`ALLOWED_USERS` に登録されていない人は画面を開けません（二重のチェック）。
3. データベースのスプレッドシート自体はメンバーに共有しないでください（Webアプリ経由でのみ操作します）。

## 困ったとき

| 症状 | 対処 |
| --- | --- |
| `clasp push` で「User has not enabled the Apps Script API」 | 手順 1-2 を実施し、数分待ってから再実行 |
| Webアプリに「データベースが未作成です」 | エディタで `setupSystem` を実行 |
| Webアプリに「この操作の権限がありません」 | オーナー以外のアカウントで開いている。オーナーで開くか、ALLOWED_USERS に登録 |
| 自動振り分けが動いていない | 「設定・ログ → 自動処理」で登録状態を確認し「登録・再設定」 |
| 承認画面で「このアプリは確認されていません」 | 自分で作成したスクリプトのため。「詳細」→「（安全ではないページ）に移動」で進めます |
