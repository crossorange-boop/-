# AI統合管制システム 運用マニュアル

---

## 1. 1日の流れ

| 時刻 | システムが自動で行うこと | 人が行うこと |
| --- | --- | --- |
| 随時（5分ごと） | 未着手タスクを分類し、担当AIへ割り当て（作業待ちキューへ） | — |
| 随時（15分ごと） | 期限間近・期限超過を通知、後続への影響と再調整案を作成 | 通知を確認 |
| **7時** | **朝の当日タスク一覧**を作成 | ダッシュボードの「今日のレポート」で今日の予定を確認 |
| 日中 | — | 作業待ちキューから指示書をコピーして各AIへ依頼 → 成果物を登録 → 確認・承認 |
| **13時** | **昼の中間経過**を作成（午前の完了・今日期限の残り・午後に優先するタスク・止まっているタスク） | 午後の優先順位を確認・調整 |
| **17時** | **夕方の進捗集計**を作成（本日完了・プロジェクト別進捗・明日期限・エラー） | 明日の準備、遅れの対処 |
| 3時 | データベースのバックアップ | — |

## 2. 基本の作業手順

### 2-1. プロジェクトを登録する
「プロジェクト → 新規」で、名前・目標・優先度・期限を入力します。

### 2-2. タスクを登録する
プロジェクト詳細の「タスク追加」または「タスク → 新規」。
- **タスク名・説明**：割り振りルールはここに含まれるキーワードで担当AIを判定します（例：「Instagram」→ Muse、「バナー」→ Canva、「開発」→ Claude Code）。
- **担当AI**：空欄なら自動で割り振ります。指定するとそのAIに固定されます。
- **依存タスク**：先に完了が必要なタスク。前提が終わるまで自動で「前提タスク待ち」になります。
- **AIへの指示書・資料URL**：各AIに渡す内容です。資料は Google ドライブの共有リンク（https）を入力します。

### 2-3. 作業待ちキューから各AIへ依頼する
1. 「作業待ちキュー」を開くと、AI別に担当タスクが並んでいます（すぐ割り振りたい場合は「今すぐ振り分け」）。
2. 「指示書をコピー」→ 各AI（Claude Code・Muse・Canva など）に貼り付けて依頼します。
   - コピーできない環境では「表示」から文章を選択してコピーします。
3. 依頼したら「着手」を押します（状態が「作業中」になります）。

> Phase 1 では、システムから各AIへ自動送信はしません。外部サービスの非公式な自動操作も行いません。

### 2-4. 成果物を登録する
タスク詳細の「成果物を登録」で、ファイル名と Google ドライブのリンクを登録します。
- 同じファイル名で再登録すると版（v2, v3…）が自動で上がります。
- 登録するとタスクは「成果物確認中」になります。

### 2-5. 確認・承認する
「成果物・承認」画面で確認します。
- **成果物の承認**：タスクは完了（承認が必要なタスクは「人間の承認待ち」）になります。
- **差し戻し**：理由を入力すると、タスクは「作業中」に戻ります。
- **承認待ち**（オーナーのみ）：プロジェクト削除、完了承認などを承認・差し戻しします。

---

## 3. タスクの状態

| 状態 | 意味 | 主に誰が変えるか |
| --- | --- | --- |
| 未着手（BACKLOG） | 登録直後 | 自動で分類されると「実行可能」へ |
| 実行可能（READY） | 分類済み・割り当て待ち | 自動で担当AIへ割り当て |
| 担当割当済み（ASSIGNED） | 作業待ちキューに表示 | 人が「着手」 |
| 作業中（IN_PROGRESS） | AIに依頼済み | 人が成果物を登録 |
| 外部AIの利用待ち（WAITING） | 担当AIが停止・利用制限中 | AIが復旧すると自動で再開 |
| 前提タスク待ち（BLOCKED） | 依存タスクが未完了 | 前提が完了すると自動で解除 |
| 成果物確認中（REVIEW） | 成果物の確認待ち | 人が承認・差し戻し |
| 人間の承認待ち（APPROVAL） | オーナーの承認待ち | オーナーが承認 |
| 完了（COMPLETED） | 完了 | — |
| 失敗（FAILED） | やり直しが必要 | 人が「再実行」（上限あり） |
| キャンセル（CANCELLED） | 中止（理由必須） | 人のみ。取り消しも可能 |

## 4. AIが使えなくなったとき（障害時の対応）

1. 「AIエージェント」で該当AIの「状態を変更」を開き、稼働状態（利用不可・メンテナンス中）または利用制限（利用制限中）を設定します。メモに理由や復旧予定を書いておくと便利です。
2. 自動処理が、そのAIの「担当割当済み」タスクを **「外部AIの利用待ち」** にします。タスクの内容・指示書・資料は **削除されません**。
   - 「作業中」のタスクは状態を変えず通知だけ出します（必要なら手動で利用待ちに）。
   - 同じ能力を持つ別のAIがいる場合、新しいタスクはそちらに割り当てられます。
3. 復旧したら状態を「利用可能／制限なし」に戻します。次回の自動処理（5分以内）で、利用待ちのタスクが **自動で再開候補** に戻り、再び割り当てられます。

> 人が手動で「外部AIの利用待ち」にしたタスク（例：素材待ち）は、自動では戻りません。

---

## 5. 失敗したタスクの再実行

- タスク詳細の「再実行」で「実行可能」に戻し、次の自動振り分けで再度割り当てます。
- 回数の上限は設定値 `MAX_RETRY_COUNT`（初期3回）。上限に達したら内容を見直し、オーナーが「上限を超えて再実行」します。
- 自動処理で失敗したもの（Phase 2 の外部連携など）は、上限までは自動で再投入されます。上限に達すると重要通知が出ます。

---

## 6. 割り振りルールの調整

「設定・ログ → 割り振りルール」（変更はオーナーのみ）。
- 上から順（優先順位の小さい順）に判定し、最初に一致したルールで分類します。
- キーワードは「|」で区切って複数指定できます（例：`デザイン|バナー|チラシ`）。
- 「試し判定」にタスク名を入れると、どのAIに割り振られるかを事前に確認できます。
- 使わなくなったルールは「有効」のチェックを外して無効化します（削除はしません）。
- 新しいAIを追加したら、そのAIの「能力」と一致する「必要な能力」のルールを作ります。

---

## 7. 設定値の変更

「設定・ログ → 設定値」（オーナーのみ）。主な項目：

| 項目 | 初期値 | 説明 |
| --- | --- | --- |
| QUEUE_CHECK_INTERVAL_MIN | 5 | 自動振り分けの間隔（1/5/10/15/30分） |
| DEADLINE_CHECK_INTERVAL_MIN | 15 | 期限確認の間隔 |
| DAILY_PLAN_HOUR / MIDDAY_CHECK_HOUR / DAILY_SUMMARY_HOUR | 7 / 13 / 17 | 朝・昼・夕のレポート時刻 |
| BACKUP_HOUR | 3 | バックアップ時刻 |
| DEADLINE_WARNING_HOURS | 48 | 「期限が近い」とみなす時間 |
| MAX_RETRY_COUNT | 3 | 再実行の上限 |
| BACKUP_RETENTION_COUNT | 14 | バックアップの保持世代数 |
| APPROVAL_REQUIRED_ACTIONS | SEND_EMAIL,PUBLISH,ORDER,PAYMENT,DELETE_PROJECT,BULK_DELETE | 人の承認が必須の操作 |
| ALLOWED_USERS | （空） | 追加利用者（`メール:EDITOR` など） |

- 時刻・間隔を変更すると、登録済みの定期処理は **自動で再設定** されます。
- 無料枠の目安：初期設定で1日約390回・推定65分（Google Workspace の上限は1日6時間）。間隔を1分にすると回数が5倍になるため注意してください。

---

## 8. 重要操作の承認ルール

次の操作は、初期段階では必ずオーナーの承認が必要です（`APPROVAL_REQUIRED_ACTIONS`）。

- メール送信／外部公開／発注／支払い／プロジェクト削除／一括削除

Phase 1 のシステムは、メール送信・公開・発注・支払いを **自動では実行しません**。「成果物・承認」画面で承認の記録を残し、実際の操作は人が行います。

---

## 9. 権限

| ロール | できること |
| --- | --- |
| OWNER（セットアップしたアカウント） | すべて（承認・設定変更・定期処理・復元・自己診断を含む） |
| EDITOR | プロジェクト・タスク・AI・成果物の登録と編集、状態変更、振り分けの手動実行 |
| VIEWER | 閲覧のみ |

---

## 10. 定期点検（月1回の目安）

1. 「設定・ログ → システム情報 → 導入確認」で「点検する」→ すべて「問題なし」を確認。
2. 「設定・ログ → 実行履歴」で結果「失敗」を絞り込み、エラーが続いていないか確認。
3. 「システム情報 → データ量」がセル上限の 50% を超えていないか確認（超えた場合は古い実行履歴の整理を検討）。
4. バックアップフォルダに直近の複製があることを確認。

## 11. よくある質問

**Q. PC を閉じても動きますか？**
A. はい。定期処理は Google のサーバー上で動きます。「設定・ログ → 自動処理」で6件が「登録済み」なら動作しています。

**Q. 自動振り分けされないタスクがあります。**
A. どのルールにも一致していません。通知「自動分類できませんでした」が出ています。担当AIを手動で設定するか、割り振りルールを追加してください。

**Q. 通知が多すぎます。**
A. 同じタスクの同じ種類の通知は、未読のうちは重複して作られません。「通知 → すべて既読」で整理できます。

**Q. 間違えて削除しました。**
A. 「設定・ログ → 削除済み」から復元できます（オーナーのみ）。詳しくは「バックアップ・復旧手順書」を参照してください。

**Q. 画面に「他の操作で更新されています」と出ました。**
A. 別の画面・端末で同じデータが更新されています。再読み込みしてからやり直してください（上書き事故を防ぐ仕組みです）。
