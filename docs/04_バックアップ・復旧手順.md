# AI統合管制システム バックアップ・復旧手順書

---

## 1. データの保存場所

| 種類 | 保存場所 | 備考 |
| --- | --- | --- |
| 業務データ | Google ドライブ「AI統合管制システム_DB」（スプレッドシート・11シート） | Webアプリ経由で操作する |
| 自動バックアップ | Google ドライブ「AI統合管制システム_バックアップ」フォルダ | 毎日3時に複製、14世代保持 |
| 成果物 | 各自の Google ドライブ（リンクのみシステムに登録） | ファイル本体はシステム外 |
| 設定情報（DBのID等） | Apps Script のスクリプトプロパティ | コード・シートには含めない |
| プログラム | GitHub `crossorange-boop/-` の `ai-control-system` ブランチ | 認証情報は含まない |

場所は「設定・ログ → システム情報」のリンクからも開けます。

---

## 2. バックアップの仕組み

- **自動**：毎日3時（`BACKUP_HOUR`）に、データベースを丸ごと複製します。
  - ファイル名：`AI統合管制システム_DB_backup_YYYYMMDDHHMM`
  - 保持世代数（`BACKUP_RETENTION_COUNT`、初期14）を超えた古いものは **ゴミ箱** に移します（完全削除はしません。ゴミ箱から約30日間は戻せます）。
- **手動**：「設定・ログ → 自動処理 → 今すぐバックアップ」（オーナー）。大きな変更の前に実行してください。
- **履歴**：Google スプレッドシート自体の「ファイル → 変更履歴」も利用できます（Google 標準機能）。
- **変更履歴（AuditLogs）**：すべての登録・更新・削除・状態変更が、変更前と変更後の内容とともに記録されています。
- **論理削除**：画面からの削除は行を消さず「削除済み」の印を付けるだけです。

### 外部への控え（任意・推奨：月1回）
最新のバックアップファイルを開き「ファイル → ダウンロード → Microsoft Excel」で保存しておくと、Google アカウントに問題が起きた場合の備えになります。

## 3. 復旧手順（ケース別）

### ケース1：プロジェクト・タスクを誤って削除した
1. 「設定・ログ → 削除済み」を開きます（オーナー）。
2. 対象の「復元」を押します。
   - プロジェクトを復元すると、一緒に削除された配下のタスクも戻ります。
   - 依存関係は復元されないため、必要ならタスク編集で再設定します。

### ケース2：内容を誤って書き換えた
1. 「設定・ログ → 変更履歴」で対象（例：タスク）と日付で絞り込みます。
2. 「詳細」で変更前の内容を確認します。
3. 画面から該当項目を元の値に編集し直します。

### ケース3：データベース全体を過去の状態に戻したい（大規模な破損など）

> 作業中に自動処理が動かないよう、最初に定期処理を止めます。

1. 「設定・ログ → 自動処理 → すべて停止」。
2. 念のため、現在のデータベースも「今すぐバックアップ」で控えます（できない場合はスプレッドシートを手動でコピー）。
3. バックアップフォルダから戻したい日時のファイルを選び、右クリック →「コピーを作成」。
4. 作成したコピーを開き、URL の `/d/` と `/edit` の間の文字列（スプレッドシートID）を控えます。
5. Apps Script エディタ →「プロジェクトの設定（歯車）」→「スクリプト プロパティ」で
   `SPREADSHEET_ID` の値を、控えたIDに **書き換え** ます。
6. エディタで `runSelfCheck` を実行し、シート・列が「問題なし」であることを確認します（不足があれば `setupSystem` を実行）。
7. 「設定・ログ → 自動処理 → 登録・再設定」で定期処理を再開します。
8. Webアプリでデータが戻っていることを確認します。元のデータベースは削除せず、名前に「_破損」などを付けて保管しておきます。

### ケース4：特定のシートだけ戻したい
1. 定期処理を停止します。
2. バックアップファイルを開き、該当シートのタブを右クリック →「別のワークブックにコピー → 既存のスプレッドシート」で現在のデータベースへコピーします。
3. 現在のデータベースで、元のシートの名前を「Tasks_old」などに変更し、コピーしたシートの名前を元の名前（例：`Tasks`）に変更します。
4. `runSelfCheck` で確認し、定期処理を再開します。

### ケース5：プログラムを以前のバージョンに戻したい
- エディタの「デプロイ → デプロイを管理」で、以前のバージョンを選んで更新すると、Webアプリの動作を戻せます（データは変わりません）。
- コードを戻す場合は、GitHub の履歴から該当コミットを取得し `npx clasp push` します。

### ケース6：スクリプトプロパティが消えた／Apps Script プロジェクトを作り直した
1. 導入手順書の手順 3〜4 で新しいプロジェクトにコードを反映します。
2. スクリプトプロパティに次を手動で登録します（`setupSystem` を先に実行すると新しいDBが作られてしまうため、必ず先に登録）。
   - `SPREADSHEET_ID`：既存データベースのID
   - `BACKUP_FOLDER_ID`：バックアップフォルダのID（フォルダURL の `/folders/` 以降）
   - `OWNER_EMAIL`：オーナーのメールアドレス
3. `setupSystem` → `runSelfCheck` → `setupTriggers` の順に実行し、Webアプリを再デプロイします。

---

## 4. 注意事項

- データベースのスプレッドシートを直接編集すると、変更履歴（AuditLogs）に残らず、整合性が崩れることがあります。通常は必ず Webアプリから操作してください。
- 1行目（列名）は変更・削除しないでください。列の並び替えや末尾への列追加は問題ありません。
- スクリプトプロパティの値（ID等）は第三者に共有しないでください。
- バックアップフォルダを他の人と共有しないでください（業務データの複製が入っています）。
